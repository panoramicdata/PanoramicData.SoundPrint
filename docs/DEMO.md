# Browser demo

`PanoramicData.SoundPrint.Demo` is a Blazor WebAssembly app that runs the whole library in the browser. There is no server component: audio is captured or decoded in the page, fingerprinted by the .NET library compiled to WebAssembly, and matched against a catalogue held in browser memory. Nothing is uploaded, which also makes it a working preview of local fingerprint extraction.

## Run it

```shell
dotnet run --project PanoramicData.SoundPrint.Demo
```

Open the address it prints. To publish static files for any web host:

```shell
dotnet publish PanoramicData.SoundPrint.Demo -c Release -o artifacts/demo
```

and serve `artifacts/demo/wwwroot` (it is plain static content). Microphone access needs a secure context: `localhost` or HTTPS.

## Pages

| Page | What it does |
|---|---|
| **Overview** | Generates the starting catalogue in the browser (eight synthetic songs, about 37,000 landmarks) and shows what the library is. |
| **Identify** | Listen through the microphone, or feed a file in as if it were a live stream. Shows the live spectrogram, the constellation of peaks in the current twelve-second window, the recognised track with its matched span, confidence and votes, and a timeline of what has been heard. A "play a catalogue track" panel lets your speakers act as the radio for the microphone. |
| **How it works** | Fingerprints the first 12 seconds of a track and draws the peaks and landmark pairs, lists sample hashes with what each encodes, and runs a clip against the catalogue to show the offset histogram whose spike identifies the track. `explain?auto=true` runs both demonstrations on load. |
| **Catalogue** | Lists tracks and lets you add your own audio file, which is decoded and fingerprinted locally. |

## Why synthetic songs

The repository contains no recordings. The demo's catalogue is generated by `PanoramicData.SoundPrint.SyntheticAudio.SyntheticSong`: deterministic music with its own tempo, key, harmony, melody, drums and tuning per seed. It is real audio you can play, so the microphone round trip is a true demonstration, but it is not copyrighted music. Add your own files to the catalogue to try the library on real tracks; they never leave your browser.

## How it is built

- `Services/DemoCatalogue.cs` holds an `InMemoryFingerprintStore` and a `Matcher`, generates the starting songs, and fingerprints added files.
- `Services/IdentifySession.cs` turns incoming 16-bit PCM into a live fingerprint (`Fingerprinter` with a `PeakObserver`), keeps a `RollingLandmarkWindow`, and matches it every 1.5 s of audio. It is covered by unit tests (`DemoServicesTests`).
- `wwwroot/js/audio.js` is the only browser-specific code: an `AudioWorklet` taps the microphone, `decodeAudioData` decodes files, and a few canvas helpers draw the spectrogram and constellation. Audio is converted to 16-bit PCM and handed to .NET; it goes no further.

## Limits

- WebAssembly runs several times slower than native code, but extraction is still many times faster than real time. Building the starting catalogue takes a few seconds.
- The demo does not persist anything: refresh the page and your added tracks are gone. Persistence belongs in a server-side store such as `PanoramicData.SoundPrint.Postgres`.
- A browser tab capturing a speaker through a microphone adds room acoustics and noise; expect it to need a few seconds longer than a direct feed.

## Hosting it (GitHub Pages)

The repository publishes the demo to the `gh-pages` branch with `.github/workflows/pages.yml` on every change to the library or the demo. The workflow copies `index.html` to `404.html` (so deep links such as `/explain` load the app), adds `.nojekyll`, and writes a `CNAME` file for the custom domain.

To host your own copy:

1. Fork the repository, then in **Settings, Pages** choose **Deploy from a branch**, branch `gh-pages`, folder `/ (root)`.
2. Change the domain in the `CNAME` line of `pages.yml`, or delete the line to use `https://<you>.github.io/<repo>/` (in that case also set `<base href>` in `PanoramicData.SoundPrint.Demo/wwwroot/index.html` to `/<repo>/`).
3. For a custom domain, add a DNS `CNAME` record from your host name (for example `soundprint`) to `<you>.github.io`, then tick **Enforce HTTPS** once GitHub has issued the certificate.

Any static host works as well: publish with `dotnet publish PanoramicData.SoundPrint.Demo -c Release -o site` and serve `site/wwwroot` with a rule that returns `index.html` for unknown paths.
